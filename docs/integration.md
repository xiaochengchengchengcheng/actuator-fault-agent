# 数据与系统接入指南

## 报警触发接口

产线报警装置、EOL 测试设备、视觉检测系统或 MES 可以向
`POST /v1/alarms/events` 推送统一事件。事件至少包含：

- 唯一 `event_id`，用于追踪和生产环境去重。
- 报警来源、执行器 ID、工位、报警码和报警描述。
- 严重度和发生时间。
- 可选的现场测量；未提供时 Agent 会继续调用测量 API。

项目中的 `AlarmIngestionSkill` 负责把不同触发入口转换为统一图状态。正式部署时建议在
报警设备与 Agent 之间增加边缘网关、MES 或消息队列，由适配器完成认证、限流、重试、
持久化和字段映射。当前 webhook 支持可选的 `X-Alarm-Token` 共享密钥；生产环境应进一步
使用 API 网关、mTLS 或设备身份认证。

报警进入后不会直接送给大模型。系统先拉取实时数据并执行确定性异常识别，再将报警内容、
实时测量和异常特征组合为第二阶段检索语句。知识库返回的解决办法连同原始证据一起交给模型。

## 测量数据接口

`TelemetryRepository` 是产线数据边界。演示实现读取 JSON；生产实现应返回同一 `MeasurementSnapshot` 结构，并保留采集时间、工位、单位、质量码和数据来源。

建议优先接入以下字段：

- 电气：母线电压、相电流、空载电流、绕组电阻、绝缘电阻、耐压结果。
- 机械：输出扭矩、反向间隙、传动效率、轴向游隙、摩擦力矩。
- 动态：振动 RMS、噪声、位置误差、速度波动、温升。
- 过程：压装力位移曲线、拧紧扭矩角度、点胶重量、校准偏置、工艺版本。

## 知识入库

示例检索器按 Markdown 文件加载知识。生产知识应至少带有以下元数据：

- `document_id`、标题、版本、生效日期和审批状态。
- 产品族、型号范围、工序、工位和故障代码。
- 密级、访问角色和所属工厂。
- 原始文件页码或段落锚点，便于追溯。

建议分块边界优先服从“一个故障模式及其验证步骤”，不要只按固定字符数切分。型号、故障代码和关键尺寸适合关键词检索；现象描述和历史案例适合向量检索。最终结果应经过元数据过滤和重排。

## 工具权限

只读工具可以查询测量、工单和工艺版本。任何可能改变 PLC、驱动器、工艺参数或质量状态的动作都应进入独立服务，并要求人工审批、权限校验、幂等键和审计日志。

## 反馈闭环

结单时记录最终根因、采取措施、替换件、复测结果和审核人。先进入待审核案例库，通过质量或工艺人员批准后再加入正式知识索引，避免错误经验自动污染知识库。
